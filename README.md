# webapp-monitor

[![CI](https://github.com/arbtsv/webapp-monitor/actions/workflows/ci.yml/badge.svg)](https://github.com/arbtsv/webapp-monitor/actions/workflows/ci.yml)

Переносимый синтетический мониторинг веб-кабинета. Прогоняет
сценарий входа по всем узлам контура из-под учётной записи мониторинга, замеряет время
шагов, сверяет со статическими эталонами и выдаёт итог `НОРМА`/`ПРОВАЛ`. Узлы с
превышением эталона прогоняются повторно (перепроверка).

Инструмент — один каталог, переносимый копированием. Машина пользователя не обязана
иметь Node.js: всё ставится внутрь каталога. Только Windows.

## Быстрый старт

1. Скопируйте каталог на машину, запустите `install.bat` — один раз. Скачивает Node.js,
   пакеты и браузер внутрь каталога (~340 МБ); в систему ничего не пишется.
2. Скопируйте `env.example.json` в `env.json` и заполните контур, учётную запись,
   узлы, эталоны (раздел «Конфигурация» ниже).
3. Запускайте `monitor.bat`. По окончании в консоли — отчёт с `ИТОГ`, на диске —
   `report.txt` и архив со снимками экрана.
4. Периодически запускайте `prune-reports.bat`, чтобы чистить старые архивы.

## Установка (`install.bat`)

- Кладёт Node.js в `node\`, пакеты в `node_modules\`, браузер — через Playwright
  (внутри `node_modules\`). В систему ничего не пишется; системный Node.js не
  используется никогда. Батник — тонкий чисто ASCII shim: всё, кроме кодировки
  консоли, bootstrap Node и паузы из Проводника, делает Node-оркестратор
  (`scripts\install.mjs`) — поэтому установку можно запускать и из планировщика
  задач, и из порождённого процесса без консоли.
- Повторный запуск докачивает недостающее. Ключи: без ключей — показать, что будет
  скачано, и спросить согласия; `/y` — без вопроса; `/reinstall` — снести `node\` и
  `node_modules\` и поставить заново; `/?` — справка. Без ключей и без консоли
  (планировщик, перенаправленный stdin) вопрос не задаётся: печатается подсказка
  про `/y` или `/reinstall` и код `2`.
- `artifacts\`, `env*.json` не трогает никогда.
- Сеть: `nodejs.org`, `registry.npmjs.org`, `cdn.playwright.dev` (+ запасной хост
  Playwright); прокси — из `HTTPS_PROXY`, системный прокси Windows не используется.
- Коды возврата: `0` — готово; `1` — сбой шага; `2` — нет согласия, неизвестный ключ, `/?`.

## Конфигурация

Один файл — один контур (dev или прод). Имя файла передаётся первым аргументом,
по умолчанию `env.json`.

```json
{
  "environment": "prod",
  "login": "monitor-account",
  "password": "...",
  "scenario": "cabinet-first-round",
  "targets": {
    "server1": "http://sub1.host/school.html",
    "server2": "http://sub2.host/school.html"
  },
  "thresholds": {
    "signin_page_ms": { "reference": 4500, "maxRatio": 2 },
    "login_ms": { "reference": 3500, "maxRatio": 2 },
    "section_ms": { "reference": 1000, "maxRatio": 2 }
  }
}
```

- `environment` — имя контура, попадает в отчёт и статистику. Обязательно.
- `login`, `password` — учётная запись мониторинга. Обязательны.
- `scenario` — имя файла сценария без расширения (`specs/<scenario>.spec.ts`).
  Обязателен.
- `targets` — узлы контура: имя → URL точки входа. Хотя бы один.
- `thresholds` — эталоны по именам метрик сценария: `{ reference, maxRatio }` —
  положительные числа. Эталоны статичны и задаются человеком: замеры разных дней
  и узлов сравнимы напрямую.
- Невалидный конфиг — ошибка до первого входа на страницу, с указанием поля.

С поставляемыми сценариями кабинета (`cabinet-first-round`, `cabinet-dayx`,
`cabinet-second-dayx`) метрики называются `signin_page_ms`, `login_ms`,
`section_ms`. Свой сценарий объявляет свои имена, для каждого в `thresholds`
нужен порог.

Сценарии дня X сезонные: вне дня X их шаг раздела падает по таймауту (таблицы дня X
нет). В межсезонье в `scenario` ставится `cabinet-first-round` — он ждёт дерево
или таблицу дня X, что появится, и работает круглый год.

## Запуск

```
monitor.bat [конфиг] [ИМЯ=ЗНАЧЕНИЕ ...]
```

Двойной клик из Проводника — допустим: окно останется открытым и в конце дождётся
клавиши. Из открытой консоли или планировщика паузы нет. Батник — тонкий shim
(кодировка, локальный Node, делегирование); вся логика — в Node-оркестраторе, его же
удобно звать напрямую:

```
node scripts\monitor.mjs [конфиг] [ИМЯ=ЗНАЧЕНИЕ ...]
```

Все `ИМЯ=ЗНАЧЕНИЕ` уходят в среду процесса и действуют только на этот запуск. Значение
с пробелами или `& | < > ^` передавайте аргументом в кавычках целиком; двойная кавычка
внутри значения не поддерживается.

При запуске в открытой консоли монитор снимает с окна режим QuickEdit: без этого клик
в окно (выделение текста) блокировал бы запись в консоль и остановил бы прогон до
нажатия ESC. Мышиное выделение после этого недоступно — копируйте через меню консоли →
«Изменить» → «Пометить» (Ctrl+M); при закрытии окна настройка вернётся как была. Из
планировщика или с перенаправленным выводом ничего не отключается.

### Переменные окружения

| Переменная           | Назначение                                                                                                                             |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `MONITOR_CONFIG`     | Файл конфигурации; у `monitor.bat` — первый аргумент                                                                                   |
| `MONITOR_TARGET`     | Только эти узлы через запятую; неизвестное имя — ошибка со списком известных                                                           |
| `MONITOR_WORKERS`    | Сколько узлов параллельно: целое ≥ 1 или `N%` логических процессоров, по умолчанию 1; выше половины ядер — урезается с предупреждением |
| `MONITOR_TIMEOUTS`   | `debug` — таймауты для разбора (шаг 180 с, тест 900 с); по умолчанию шаг 30 с, тест 180 с; иное значение — ошибка                      |
| `MONITOR_ARTIFACTS`  | Каталог результатов вместо `artifacts`                                                                                                 |
| `MONITOR_CSV`        | Путь к `metrics.csv` вместо `<artifacts>\metrics.csv`                                                                                  |
| `MONITOR_RUN_ID`     | Свой `run_id` вместо сгенерированного                                                                                                  |
| `MONITOR_RECHECK_OF` | Служебная: оркестратор ставит её для перепроверки                                                                                      |

Недопустимое значение — ошибка до первого входа на страницу, без тихого отката
к умолчанию.

### Коды возврата

| Код | Значение                                                                                   |
| --- | ------------------------------------------------------------------------------------------ |
| `0` | Основной прогон в норме                                                                    |
| `1` | Прогон провален (порог, падение теста, ошибка отчёта) или недопустимое значение переменной |
| `3` | Окружение не готово: сначала `install.bat`                                                 |

Код возврата — только исход основного прогона; перепроверка и сборка отчёта его
не меняют.

## Что измеряется

Поставляемый сценарий кабинета идёт четырьмя шагами; каждый замер сверяется
с эталоном: превышение в `maxRatio` раз и больше — вердикт `slow`, прогон в целом
`ПРОВАЛ`:

- **Страница входа** (`signin_page_ms`) — от открытия страницы до появления поля логина.
- **Вход в кабинет** (`login_ms`) — от нажатия входа до появления кабинета.
- **Раздел кабинета** (`section_ms`) — от перехода в раздел до готового раздела.
- **Таблица раздела** — непустая таблица записей в разделе (проверка содержимого,
  не метрика).

Сценарий можно заменить своим: файл `specs/<имя>.spec.ts`, ключ `scenario` в конфиге,
ядро не правится. Отказ во входе падает сразу, с текстом ошибки со страницы, а не по
таймауту. Снимок экрана делается в любом исходе. Повторов прогона нет (`retries: 0`) —
повтор скрыл бы деградацию, ради которой делается прогон.

## Результаты

Всё копится в каталоге результатов (по умолчанию `artifacts\`):

| Файл                  | Содержимое                                                                                                                                                               |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `metrics.csv`         | Строка на замер: `timestamp,environment,target,url,metric,duration_ms,reference_ms,ratio,max_ratio,verdict,run_id`                                                       |
| `runs.csv`            | Строка на прогон: `run_id,started_at,config_file,environment,host,cpu_count,workers,targets,scenario,recheck_of,timeouts,node_version,playwright_version,bundle_version` |
| `report.txt`          | Отчёт последнего прогона, последняя строка — `ИТОГ`                                                                                                                      |
| `report_<run_id>.zip` | HTML-отчёт Playwright со снимками, `report.txt`, `run.json`                                                                                                              |
| `report.zip`          | Копия архива последнего прогона                                                                                                                                          |
| `last-run-id.txt`     | `run_id` последнего основного прогона                                                                                                                                    |

CSV только дописываются; учётные данные и адреса узлов в `runs.csv` не попадают.
История замеров — в CSV; графиков и визуализации истории в инструменте нет.

## Перепроверка

Узлы со строками `verdict=slow` основного прогона прогоняются повторно под id
`<run_id>-recheck` с отдельными выходами; основные результаты не затираются. Раздел
«Перепроверка» отчёта справочный: итог и код возврата — только по основному проходу.
Таймаут шага не оставляет строки замера — такой узел не перепроверяется.

## Чистка архивов (`prune-reports.bat`)

Удаляет `report_<run_id>.zip` старше заданного срока (по времени изменения).
Спросит срок в днях, покажет, что будет удалено, удалит после `y`/`д`. Ключи:
`--days N` — срок без вопроса; `--yes` — без подтверждения, только вместе с `--days`.
`report.zip`, CSV и отчёты текущего прогона не трогаются. Коды: `0` — готово, отказ
или удалять нечего; `1` — часть файлов не удалена; `2` — неверный ввод; `3` — не
найден Node.js.

## Сеть для `install.bat`

Нужен доступ к `nodejs.org`, `registry.npmjs.org`, `cdn.playwright.dev` (и запасному
хосту Playwright). Прокси берётся из `HTTPS_PROXY`; системный прокси Windows не
используется — браузер идёт к целям напрямую, чтобы прокси не шумел в замерах.

## Перенос и обновление

Каталог переносится копированием целиком; после переноса `install.bat` докачает
недостающее. Другой контур — другой конфиг (`monitor.bat env.prod.json`), запуск
по расписанию — внешним планировщиком ОС (`node scripts\monitor.mjs ...`).
