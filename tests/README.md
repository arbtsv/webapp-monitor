# Проверки бандла

Офлайн-обвязка разработчика: проверяет правки бандла без сети и без живого кабинета.
Пользователю бандла не нужна. Node-часть работает только на Windows (`monitor.bat` идёт через
`cmd.exe`). Сверки дублей `test_parity_*.py` требуют Python 3 и pytest, сами тесты — только на
stdlib.

## Запуск

Команды `npm run test:*` — из каталога бандла: npm исполняет скрипт через `cmd.exe` из любой
оболочки. В PowerShell — `npm.cmd run …`: политика выполнения может блокировать `npm.ps1`.
Обвязку напрямую — через `node`, а не через `cmd.exe` из Git Bash (там `/c` стал бы путём).
Прогоны — строго по очереди: у фиктивного кабинета фиксированный порт.

Строка таблицы называет область бандла, а не случаи: случаи — в самом файле обвязки, у
`*.unit.ts` их перечислит `npm run test:unit -- --list`.

| Что проверяет                                                                                                                                                    | Команда                                                                                                                                                                                                       |

## Коды возврата

`bat-args.mjs`: 0 — все случаи OK, 1 — хотя бы один FAIL, 2 — сбой самой обвязки (причина —
строкой `[bat-args] …`). `fake-cabinet.mjs` возвращает код `monitor.bat`.

`--bat` с `env.fake-full.json` и смоук завершаются кодом 1 ожидаемо: в наборе есть медленные
и сломанные узлы. Поэтому `npm run test:smoke` и `npm run test:fake` идут через обёртки
`run-smoke.mjs` и `run-fake.mjs` (общий код — `run-lib.mjs`), которые сверяют исход сами: код
каждого шага и ожидаемые/запрещённые строки вывода (`ИТОГ`, раздел «Перепроверка», статусы
узлов). Их коды: 0 — исход ожидаемый, 1 — неожиданный, причина — строкой `[run-smoke] …`/
`[run-fake] …`, 2 — сбой самой обёртки. Шаг отчёта смоука ждёт код 0: `report.mjs` выходит
кодом 1 только при собственном сбое, а не по вердикту.

## Что нужно для запуска

`fake-cabinet.mjs`, смоук и юнит-тесты работают на настоящем бандле: нужен его `node_modules`
(его ставит `install.bat`). `bat-args.mjs` и `install-bat.mjs` гоняют настоящие bat-файлы
на копиях с заглушками оркестратора: `node_modules` бандла не нужен, нужен системный Node
в PATH; `install-bat.mjs` копиям подкладывает и локальный `node\node.exe` (копия системного),
чтобы shim не уходил в сетевой bootstrap.

Результаты и копии — под `artifacts/_dev/` (gitignored), после прогона остаются для разбора.
Рабочий `artifacts` не трогается: переменные `MONITOR_*` оболочки обвязка отбрасывает и
выставляет свои.

## Контракт дублей

Скрипты отчёта идут без сборки TypeScript, поэтому константы продублированы между
`.mjs` и `.ts`: `sanitize` в `helpers/artifacts.ts` и `scripts/common.mjs` сверяет
`test_parity_sanitize.py`; одноимённые однострочные константы `scripts/common.mjs` и
`helpers/*.ts`, выходы `playwright.config.ts` и суффикс перепроверки в
`helpers/global-setup.ts` — `test_parity_constants.py`. Правка в одном месте без
остальных ломает бандл молча. Константу, повторённую под другим именем или встроенную
литералом в новом месте, тест не ловит — такую пару дописывают в тест вручную.

## Ловушки и границы

- **Поведение узлов фиктивного кабинета** — таблица `NODE_BEHAVIOR` в `fake-cabinet.mjs`:
  обычный, задержка один раз/всегда, сломанный вход, ошибка входа, stalled (ответа нет
  никогда — шаг падает по таймауту навигации и узел не перепроверяется). Таблица дня X
  рисуется рядом с деревом — все поставляемые сценарии проходят на фиктивном кабинете.
- **Вариант прогона — аргументом после конфига, не переменной оболочки:**
  `--bat <конфиг> MONITOR_WORKERS=2`. Строже, чем у `monitor.bat`: принимаются только имена
  из `VARIANT_NAMES` со значением, безопасным для строки `cmd /c` (`PAIR_RE`), остальное — код
  2 с причиной.
- **Граница `--explorer`.** Он передаёт конфиг аргументом, а настоящий двойной клик идёт без
  аргументов: тогда `monitor.bat` берёт `env.json` своего каталога — настоящего каталога
  бандла, куда фиктивный конфиг не подставить.
- **`install.bat` покрыт обвязкой** (`install-bat.mjs` — shim-границы, `install.unit.ts` —
  логика оркестратора); успешный путь bootstrap со скачиванием Node и шаги npm ci/браузера
  с сетью обвязкой не гоняются — только вручную на настоящей машине. `prune-reports.bat`
  обвязкой не покрыт: отбор архивов в `scripts/prune-reports.mjs` проверяет
  `prune-reports.unit.ts`, сам bat — ничего.
- **Остаточный фоновый `--serve`.** Симптом — `[fake-cabinet] порт 18480 не открыт`: от
  прошлого прогона остался процесс `fake-cabinet.mjs --serve`. Снять из любой Windows-оболочки
  PowerShell-командой по `CommandLine`:
  `Get-CimInstance Win32_Process -Filter "Name='node.exe'" | ? CommandLine -like '*fake-cabinet.mjs*--serve*' | % { Stop-Process -Id $_.ProcessId }`.
